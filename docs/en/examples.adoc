== Message examples

The samples are part of the specification package `{schema-uri}.zip` (directory `samples`).

Within a location, the description by each method is preceded by an XML comment with its name: `<!-- OpenLR -->`,
`<!-- ALERT-C -->`, `<!-- GN -->`,
`<!-- gmlLineString -->` (location path), and for separate carriageways `<!-- GN firstDirection -->` and
`<!-- GN oppositeDirection -->`. The comments use model names, are language-neutral and are meant for human
readers only.

=== predefined_location_set-fcd.xml – FCD sections

Four sections of the FCD set – between ALERT-C locations 2125 and 15781 and between locations 25575 and
1325 (motorway), each direction as a separate location (GN network 26.06). The sections `TS02125T15781` and
`TS25575T01325` are also used in the samples of the format `x-format:cz-ndic_d2-fcd-status-v2.0`.

[source,xml]
----
include::{samplesdir}/predefined_location_set-fcd.xml[tags=**]
----

Envelope and header::
Root `d2:payload` of type `loc:PredefinedLocationsPublication` with the `@profileName` and `@profileVersion`
attributes; `feedType` refers to the distribution (data source).

Location::
One-directional linear location without a name, described by OpenLR (`firstDirection` only), ALERT-C
(`alertCAffectedDirection` = `aligned`) and Global Network sections in the order of travel. The location path is carried by `gmlLineString` and
`coordinatesForDisplay`. The second location is the same section in the opposite direction; the road has
separate carriageways here, so the opposite direction consists of other Global Network sections.
+
FCD sections are always one-directional: speed and travel time are evaluated for each direction of travel
separately, so each direction of the same section is a separate location with its own identifier
(`TS02125T15781` and `TS15781T02125`) and its own description by all methods. This is specific to FCD
sections; other locations, e.g. road weather station sections, describe both directions by one
bidirectional location (<<smer>>).

=== predefined_location_set-weather.xml – road weather station sections

Three road weather station sections of the weather set (GN network 25.12, data of 30{nbsp}September 2026). The
first section (7 83.427) is referenced by the sample `aquaplaning.xml`, the second (Cínovec 2) by the sample
`strong-wind.xml` of the `x-format:cz-ndic_d2-weather-v2.0` format.

[source,xml]
----
include::{samplesdir}/predefined_location_set-weather.xml[tags=**]
----

Location::
Road weather station sections are valid in both directions (`alertCAffectedDirection` = `both`). In all three
locations the same GN sections serve both directions (`directionRelativeOnLinearSection` = `both`). The location path in
ETRS89 is carried by `gmlLineString`. The excerpts used in the chapter on location referencing (ALERT-C, location
path) are marked in the first location.

=== predefined_location_both-directions.xml – bidirectional locations

Two bidirectional locations (GN network 25.12) with both directions described in OpenLR
(`firstDirection`, `oppositeDirection`).

[source,xml]
----
include::{samplesdir}/predefined_location_both-directions.xml[tags=**]
----

Sections serving both directions::
II/230 Zádub-Závišín: the opposite-direction sections mirror the first direction, so they are given once
with `directionRelativeOnLinearSection` = `both`, including both full inner sections.

Separate carriageways::
I/30 in Ústí nad Labem: the opposite direction runs on different, one-way sections; the whole route of the
first direction (three sections) is followed by the whole route of the opposite direction (three sections),
all as `linearWithinLinearElement`. Each route is preceded by the comment `<!-- GN firstDirection -->` or
`<!-- GN oppositeDirection -->`; `gmlLineString` runs along the
carriageway of the first direction.
