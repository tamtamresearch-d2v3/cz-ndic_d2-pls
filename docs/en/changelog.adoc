== Documentation change history

// Documentation revisions (MAJOR.MINOR.REVISION). Format changes: see CHANGELOG.adoc in the specification.
=== 2.0.0

* New documentation of the `cz-ndic_d2-pls` format version 2.0 (DATEX II 3.7); replaces the documentation
  of the cz-ndic_d2-predefined-location-set-v1.2 format (DATEX II 2.3).
* Changes compared to version 1.2 (DATEX II 2.3):
** The `d2LogicalModel` and `exchange` envelopes are not used; the root is `d2:payload`, the format is
   identified by the `@profileName` and `@profileVersion` attributes, `feedType` references the
   distribution, `feedDescription` is not used.
** A location is `predefinedLocationReference` of type `loc:PredefinedLocation` (formerly
   `predefinedLocationContainer`), a group is of type `loc:PredefinedLocationGroup` (formerly
   `PredefinedNonOrderedLocationGroup`).
** Location identifiers and versions do not change; references in existing data remain valid.
** The national location extensions (`linearExtension`, `globalNetworkLinear`, `openlrExtendedLinear`) were
   replaced by elements of the 3.7 model: OpenLR in `openlrLinear` (`firstDirection`, `oppositeDirection`),
   Global Network sections in `linearWithinLinearElement` with `loc:LinearElementByCode`.
** The start and end of a GN location (`startPoint`, `endPoint` in S-JTSK) are replaced by the location path
   in ETRS89 (`gmlLineString`) and a display point (`coordinatesForDisplay`); GN edge sections use percentages.
** Percentages of the GN section length are in the range 0–100 (formerly 0–1).
** Bidirectionality in GN (`directionality`, `oppositeDirection`) is expressed by direction `both` (only for
   sections passable in both directions), otherwise by the whole opposite-direction route after the route of
   the first direction; each route is preceded by an XML comment.
** The ALERT-C country code is `2` (formerly `CZ`); new mandatory element `alertCAffectedDirection`.
** OpenLR classes have different element names in the 3.7 model (`openlrCoordinates`,
   `openlrLowestFrcToNextLRPoint`) and road class values in lower case (`frc0`–`frc7`).
** Point locations are not used.
** A permanent location over several roads is described by a predefined itinerary `loc:PredefinedItinerary`
   whose parts (`predefinedLocation`) each lie on one road and are in the order of travel.
